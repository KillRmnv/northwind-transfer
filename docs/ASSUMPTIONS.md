# ASSUMPTIONS

Неоднозначности ТЗ и как они разрешены. Открытые пункты помечены [OPEN].

## A1. Округление и split scale

ТЗ требует строки по `minor_units` на API и `NUMERIC` в БД, но не задаёт место округления. Разрешено: храним `NUMERIC(20, 8)`, округляем `HALF_UP` в одном модуле только на показе. Ставка не округляется до умножения.

## A2. Обратный расчёт TARGET

ТЗ задаёт только прямой пример. Разрешено формулой из D3 + проверка прямым прогоном; расхождение в 1 minor unit из-за округления — в пользу клиента не округляем, фиксируем детерминированное правило «округление последней операции вверх» при реализации.

## A3. Свежесть курса

«Не все курсы свежие» без определения свежести. Разрешено: свежий = получен в пределах `quote_ttl_sec` направления; старше — `RATE_UNAVAILABLE`.

## A4. Тот же Idempotency-Key с другим телом

ТЗ требует идемпотентность, поведение при смене тела не задано. Разрешено: `422 IDEMPOTENCY_CONFLICT`, см. D8.

## A5. Ожидание провайдера 30 секунд

«Ждать синхронно или вернуть 202 — решите сами». Разрешено гибридом D5: ждём до таймаута, дальше `202` + поллинг.

## A6. Запасной провайдер ниже min_margin_percent

«Можно ли брать — решите и опишите». Разрешено: по умолчанию нет (`FAILED` + возврат резерва); взятие ниже минимума — только с пометкой в истории как исключение.

## A7. Неизвестный webhook

ТЗ не задаёт ответ на событие по неизвестной выплате. Разрешено: `200 + warn-лог + метрика`, не `404`, чтобы не провоцировать шторм ретраев.

## A8. [OPEN] Строгая подпись vs chaos-эмулятор

Решение D10 требует HMAC всегда, но эмулятор в chaos-режиме может слать без подписи. Первые тесты вебхуков должны это проверить. Если подтвердится — смягчить до «проверяем если секрет задан, иначе warn», с записью сюда.

## A9. Окна лимитов: границы и ноль

Для скользящих окон (7/16 дней, часовое) принято: окно полуоткрытое `[now − window, now)`, сравнение строгое (`сумма > лимит`), остаток ровно ноль — не превышение (как Java `domain-rules.md`). Временная зона — UTC, единственное место конверсии — limit-модуль.

## A10. [OPEN] Численные дефолты

Не заданы ТЗ: таймаут синхронного ожидания (10 vs 15 с), период сверки, веса скоринга `w1/w2/w3`, дефолт часового лимита (`daily / 6`). Выбрать при реализации, обосновать в `DECISIONS.md`.

## A11. Ошибка vsahayta. Формат ошибок

ТЗ требует `{"error": {"code", "message", "details"}}`, SPEC добавляет RFC 9457. Разрешено: оба одновременно — RFC 9457 сверху (`type/title/status/detail/instance`), вложенный `error` внутри, `Content-Type: application/problem+json`.

## A12. Естественные ключи справочников

Коды справочников — верхний регистр (`RUB`, не `rub`), валидация в API на входе. Переименование кода (деноминация, смена ISO) — миграция с `UPDATE CASCADE`, а не правка строк руками. Сиды идемпотентны: повторный прогон не дублирует справочники (`ON CONFLICT DO NOTHING` / проверка по коду).
