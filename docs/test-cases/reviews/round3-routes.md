## Подтверждённые баги (факт проверен кодом/прогоном, не мнением)

1. **404/405 вне problem+json.** Живой запрос: `GET /no-such-route` → `404 application/json {"detail":"Not Found"}`; `DELETE /quotes/{uuid}` → `405 application/json {"detail":"Method Not Allowed"}`. Причина — нет хендлера `StarletteHTTPException` (`app/main.py:80-83`). Контракт §6 «Ошибки» требует единый формат — нарушен именно на этих путях.
2. **Двойной запрос attempts в `load_transfer_view`.** `build_history` (`app/api/v1/transfers.py:25`) + повторный `latest_attempts` (`:48`). Каждый `GET /transfers` и каждый `POST /transfers` (через `load_transfer_view` в `:92`) делает лишний SQL.
3. **`build_history` не отсортирована по времени.** Порядок фиксирован `[PENDING, attempts, events, final]`, §7 прямо допускает webhook не по порядку — история может врать о последовательности. Тесты требуют лишь `len >= 2`.
4. **`202 + Location` на терминальном FAILED.** `respond_with_outcome` (`app/api/v1/transfers.py:52-57`): любой не-`COMPLETED` → `202 + Location`, включая `FAILED`. Клиент по семантике `202` будет опрашивать завершённый перевод.
5. **Body/path расходятся по UUID.** `TransferRequest.quote_id: FlexibleUUID` принимает `hex-без-дефисов/{braces}/urn:`, а `GET /transfers/{id}` / `GET /quotes/{id}` (`UUID`) — нет. Тот же id из ответа `POST` может не открыться через `GET`.
6. **`KeyError` вместо 4xx на неизвестной валюте в мапперах.** `mappers.py:12` (`minor_units[currency]`), `mappers.py:93-97` — любая валюта вне справочника → 500 INTERNAL_ERROR. Проверено прогоном.
7. **`GET /clients/{id}/balance` для неизвестного клиента — 422 вместо 404** (`transfers.py:120` `ValidationError`), в то время как соседи дают 404 через `*NotFoundError`. Мелочь, но контракт ответов несогласован.

## Не покрыто (нужны тесты/прогоны с БД — из песочницы 5433 недоступен)

- `load_transfer_view` при конкурентном `webhook/reconcile` между чтением `transfer` и `attempts/events` (статус vs хвост истории); отсутствие refresh при `expire_on_commit=False`.
- `GET /transfers/{valid-but-missing}` → 404 TRANSFER_NOT_FOUND problem+json (код очевиден, живого прогона не было — нужен DB).
- `GET /quotes/{hex-без-дефисов}` → ожидаемо 422 (строгий `UUID` в path); `POST /transfers` с `quote_id` вида `{braces}`/`urn:` — поведение `TransferRequest` проверено без БД (ок), сквозной прогон с БД отсутствует.
- Границы `Idempotency-Key`: `None`/пусто/пробелы/unicode/`"x"*128` — логика проверена прогоном функции, HTTP-сквозных тестов в репо нет (есть только 129).
- `build_history` при большом числе попыток/событий (рост ответа, порядок при out-of-order webhook).
- `X-Request-ID` на 500 из `unhandled_error_handler` и на обрыве middleware (требует инжекта исключения).
- `problem+json` на 404/405 после фикса; дубли роутов — отсутствие расхождения схем при росте API (регрессионный тест OpenAPI).
- `read_balance` 422-vs-404 для неизвестного клиента; `money()` на валютах вне справочника — только unit-прогон без БД, сквозного нет.

Примечание про окружение: `localhost:5433` из песочницы недоступен (прямое подключение виснет до таймаута), а `docker compose run` из подзадачи не запускался, чтобы не трогать общее окружение; все факты выше получены чтением кода и прогонами, не требующими БД.
