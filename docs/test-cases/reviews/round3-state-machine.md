## Подтверждённые баги

1. **P1, `repair()` — обход атомарного пути.** `transfer_machine.py:87-92` + `repositories/transfers.py:123-131`: голый статус без `funds_settled`, резерва и синхронизации попытки. Вызов из `reconcile.py:87` после проигранного `complete()` даёт `COMPLETED` с `funds_settled=false` и вечно висящим резервом. Плюс `repair` разрешает откат в `PENDING` мимо `EDGES`. Рядом мёртвый `set_status` (`repositories/transfers.py:150-153`) без WHERE-гарда и без вызывающих.
2. **P1, терминально-слепой `RETRY`.** `transfer_machine.py:78-85` не читает статус перевода; `transfers.py:349-351` продолжает цикл с новым POST на завершённый перевод. Цикл не перечитывает терминальность перед `record_attempt`.
3. **P1, лживый `"COMPLETED"`.** `transfer_machine.py:80-82`: итог `complete()` игнорируется, строка `"COMPLETED"` возвращается при проигранной гонке → `201` при `FAILED` в БД, `completed++` в сверке (`reconcile.py:89` безусловен и при `done is False`).
4. **P1, неизвестный статус выплаты.** `_parse_state` (`providers.py:223-230`) без allowlist + запись в `payout_attempts.status` с FK (`tables.py:163,176`, сид `seed.py:29`) → `IntegrityError`/500 и/или полл до дедлайна вместо карантина. Вебхук-путь защищён (`webhooks.py:50`), GET/sync/сверка — нет.
5. **P1, проигранный `start()` игнорируется.** `transfers.py:337,362,381` выбрасывают `bool` от `set_status_if_unsettled`; код идёт опрашивать провайдера и сеттлить, усугубляя п.2.
6. **P2, `CANCELLED` мёртв.** 4 ребра в `EDGES`, ноль акторов; `can()`-тест `CANCELLED`-пары не параметризует (`tests/unit/test_transfer_machine.py:31-44`).
7. **P2, история не аудируема.** `build_history` (`api/v1/transfers.py:23-32`): нет строк `start`/гонки/`repair`, времена — `created_at`/`received_at` вместо моментов переходов, сортировки нет, промежуточные статусы попытки затираются.

## Не покрыто

- `tests/unit/test_transfer_machine.py` (47 строк, `session=None`) тестирует только чистую `can()`: нет `start/complete/fail/settle_from_payout/repair`, нет `CANCELLED`-пар, нет гонки `rowcount==0`, нет «один settle — один эффект на баланс».
- Нет теста «два драйвера — один перевод» (sync POST + `FAILED`-вебхук + сверка одновременно; дубли `attempt_no`, двойной POST).
- Нет теста статистики сверки на проигрыше гонки / `CANCELLED` / падении `/rates` посреди `reconcile_once`.
- Нет теста replay по протухшей котировке: `POST /transfers` тем же ключом после `expires_at` дёргает `run_attempts` (`api/v1/transfers.py:90`) без перепроверки `expires_at` — возможны новые payout по мёртвой экономике.
- Нет теста монотонности штампов (`fail(now)` временем входа в роут vs свежие `attempt.updated_at`; дедлайн поллинга от времени входа, `transfers.py:410-421`).
- Нет теста аудируемости переходов в `build_history`.
- Не проверена живость `PENDING→COMPLETED` напрямую: используется ли ребро где-то кроме рестарта сверки, и должно ли оно существовать.

- `_settle`: `UPDATE … WHERE funds_settled=false AND status NOT IN (terminal)` + `rowcount==1` (`transfer_machine.py:94-104`) корректно сериализует `complete`-vs-`complete` и `complete`-vs-`fail`; денежный эффект идёт строго после выигранного гарда.

- `TERMINAL` в `services/transfers.py` — импорт из машины, дубля множества нет (дубли — только литералы в репозитории/сервисах, см. строку N).
