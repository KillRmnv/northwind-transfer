# rate-freshness — свежесть курсов и кэш

## Цель
Свежий = получен в пределах `min(quote_ttl_sec направления, 6ч)` (SPEC/A3).
Курс старше или отсутствующая пара — `RATE_UNAVAILABLE`, молчаливых подмен нет (D4).
Кэш держит шторм 50–100 параллельных, но никогда не отдаёт протухшее за свежее.

## Источник в Java
- `service/rate_cache.feature` (5 кейсов): вторая конверсия — без чтения таблицы;
  обновление видно на следующем поиске, а не по TTL; видно и для уже
  конвертированного дня (инвалидация счётчиком поколений: ключ — день, о котором
  спросили, а не день ответа); нечитаемое закэшированное выбрасывается.
- `RateCacheDisabledTests`: кэш выключен свойством — конверсия идёт из базы.
- `service/conversion_boundaries.feature`: курс берётся за день расхода, а не за
  первое число; опубликованный позже день не котирует; суббота/воскресенье —
  пятницей (порядок поиска, не свежесть).
- `service/daily_rate_sweep.feature`: непокрытый день стоит вызов (промах не кэшируется).

## Кейсы (вход → ожидание)

| # | Вход | Ожидание |
|---|------|----------|
| 1 | `now − updated_at ≤ min(quote_ttl_sec, 6ч)` | курс годен, `POST /quotes` считается |
| 2 | Курс старше `min(ttl, 6ч)` (RUB→PHP/AED протухшие) | `RATE_UNAVAILABLE` |
| 3 | Пары нет ни в какую сторону (`KZ-TH-BANK`) | `RATE_UNAVAILABLE` |
| 4 | Повторный `POST /quotes` в пределах TTL | ответ из кэша, без шторма в `mock-provider/rates` |
| 5 | Обновление курса мока внутри TTL | видно на следующем поиске (инвалидация сразу, не по TTL) |
| 6 | Битое/нечитаемое закэшированное значение | выбрасывается, идём в источник, не конвертируем мусором |
| 7 | Промах кэша («курса нет») | не кэшируется (иначе свип/обновление не пробьётся) |
| 8 | Кэш выключен (флаг) | расчёт идёт напрямую, поведение то же |
| 9 | `rates.json` как сид/фолбэк тестов | живой путь всегда идёт в `GET mock-provider/rates` (D4) |

## Адаптация под наш контракт
- Кэш на `quote_ttl_sec` направления, не на Redis TTL Java-референса; Redis как
  обязательный компонент не портируем (см. README «не перенесено»).
- Субботы/воскресенья: у Frankfurter-аналога курс есть на каждый день; правило
  «день расхода, иначе последний более ранний» сохраняется, окно запасного запроса
  — 10 дней (урок assumptions §2 п.4).
- Метрики: `rates.resolved{source,provider}`, промахи/попадания отдельно (см. load).
