# arch-boundaries — границы слоёв

## Цель
Механическое enforcement структуры `api → services → repositories → models`
(SPEC, D15): тесты падают в момент нарушения, а не «упоминают в документе».

## Источник в Java
- `ArchitectureTest` (10 правил): контроллеры не лезут в репозитории и JPA
  напрямую; сервисы не зависят от контроллеров и web-типов; репозитории не
  зависят от сервисов; мапперы — только MapStruct-интерфейсы; хендлеры исключений —
  только в `exception`-пакете; бины без состояния; транзакционные бины проксируемы.

## Кейсы (правило → что ловит)

| # | Правило (наш эквивалент) | Ловит |
|---|--------------------------|-------|
| 1 | `api` не импортирует `repositories`, `sqlalchemy`, `asyncpg` | бизнес-логика/запросы в роутере |
| 2 | `services` не импортируют `api`, `fastapi.(Request\|HTTPException\|APIRouter)` | HTTP-концерн в домене |
| 3 | `repositories` не импортируют `services`, `api` | зависимость наружу |
| 4 | `models` не импортируют `services`, `api`, `repositories` | домен тянет инфраструктуру |
| 5 | `services` не импортируют `float`-деньги (запрет `float` везде, D2) | деньги как `float` |
| 6 | Обработчики исключений — только в `api/exception_handlers.py`, один перехватчик | второй формат ошибок |
| 7 | DTO — только Pydantic v2 (`strict`), деньги — строки по `minor_units` | свободные dict-ответы |
| 8 | Общие бины/сервисы без мутабельных полей уровня инстанса | гонка в shared-сервисе |
| 9 | Комментариев `#` в коде нет (D15, кроме вендорного мока) | пояснения в коде вместо спек |
| 10 | `Field(description=…)` на каждом поле DTO | недокументированный контракт |

## Адаптация под наш контракт
- Инструмент: `importlinter`/`grimp` или AST-тест (`pytest-archon`) — выбрать
  при реализации (SPEC).
- Не портируем: MapStruct-правило (у нас Pydantic), ShedLock/CGLIB/final-правила
  (JVM-специфика), Spring-аннотации.
- Положительный контроль как в Java: правило обязано уметь падать (сломанная
  заготовка в тесте arch).

## Приоритет
**P1** (качество, защита от «быстрых» нарушений).
