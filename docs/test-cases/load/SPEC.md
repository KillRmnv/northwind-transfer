# load — нагрузка, пул и chaos

## Цель
50–100 параллельных не роняют пул и не ломают инвариант
`доступно + резерв + списано = старт`; `chaos_run.py --transfers 300` в `MOCK_MODE=chaos`
заканчивается без двойных выплат и зависших резервов.

## Источник в Java
- `service/concurrency.feature`: 50 потоков — все 50 строк, итог `5000`;
  `quota/rate_limit.feature` — граница ловится детерминированно только на
  переопределённых числах (3 токена, не прод на 60/с).
- `MetricsRecorderTest` (12 кейсов): счётчики по исходам (`flagged/within_limit/
  uncalculated` — uncalculated свой класс, не flavour of false); `rates.resolved`
  по `{source, provider}` (провал виден по провайдеру, не по сумме); таймер lookup
  считает и неуспехи; sweep — длительность и count под разными именами; ни два
  метра — одно имя; теги закрыты (без currency/account в тегах).
- `quota/rate_limit.feature` как техника: прод-числа для теста переопределять
  (маленькая ёмкость/короткий seed), иначе границу не поймать.

## Кейсы (вход → ожидание)

| # | Вход | Ожидание |
|---|------|----------|
| 1 | 50–100 конкурентных `POST /transfers` (`asyncio.gather`, `httpx`) | все доходят, нет `TimeoutError` пула |
| 2 | Состояние пула под нагрузкой | `engine.pool.checkedout()` в пределах `pool_size+overflow`, `max_connections ≥ pool×воркеры+резерв` (D13) |
| 3 | `SHOW shared_buffers/work_mem/max_connections` в testcontainers-PG | значения из `.env` применены, не дефолты |
| 4 | `pytest -n auto` | изоляция схем/БД на воркер, `engine.dispose()`, без перетекания данных |
| 5 | `slow` 30 с × много параллельных | клиенты получают `202 PROCESSING`, соединения не держатся вечно (таймаут D5) |
| 6 | `MOCK_MODE=chaos MOCK_SEED=… chaos_run.py --transfers 300` | ноль двойных выплат (ledger мока), ноль зависших резервов |
| 7 | Метрики переводов по исходам | `transfers.completed/failed{reason, provider}`; неизвестный итог — свой класс |
| 8 | Метрики курсов `{source, provider}` + таймер lookup (включая неуспехи) | провал/фолбэк виден по провайдеру |
| 9 | Имена метрик уникальны, теги закрыты | без `currency/account/transfer_id` в тегах (кардинальность) |

## Адаптация под наш контракт
- Одна команда `uv run pytest` (SPEC); нагрузочные — меткой, но в том же прогоне.
- Квоты запросов (Java `quota/`) у нас нет — не портировать как поведение;
  переиспользовать только технику «переопределённые числа для детерминизма»
  (малый seed chaos, короткий TTL в тестах).
- PG RAM из D13 обязательна до нагрузки (`shm_size: 1gb`, `shared_buffers 512MB`…),
  иначе параллельные упираются в `/dev/shm`/дефолты.
